## 1. Что это за проект

**Vasily AI** — локальный ИИ-агент на архитектуре ReAct (Reasoning +
Acting). Работает через Ollama, поддерживает плагины, градиентно-
каскадную память, структурированное логирование, watchdog и
автоматические crash-репорты.

**Ключевые принципы:**
- Всё локально, ничего не уходит в облако.
- Прозрачность: числа в памяти «трассируемы» (можно понять, почему
  факт жив или удалён).
- Агент **не знает**, какая модель крутится в Ollama — 1.5B или 32B,
  лишь бы присылала корректный JSON.
- TDD: сначала красный тест, потом код.

**Стек:**
- Python 3.14, `uv` для зависимостей
- Ollama (LLM runtime), SearXNG (поиск, локальный в Docker)
- `aiohttp`, `structlog`, `PyQt6`, `snowballstemmer`

## 3. Что уже сделано (сводка по ADR)

### ADR-013: Gradient Cascade Memory
Термодинамическая память из трёх зон:
- **TGS** (50.0–60.0) — рабочий кэш топ-10 фактов
- **HOT** (0.1–49.9) — точка входа и фильтр
- **COLD** (−49.9…−0.1) — прихожая перед удалением

Ключевые механизмы:
- 1 тик = 1 запрос = 1 `decay()`.
- Стартовое охлаждение −2.0 (кроме TGS).
- Нагрев: `recall` +5, `remember` +10, потолок 60.
- «Один нагрев за тик» через `last_heat_tick`.
- Два пути вниз: дистилляция (LLM-саммари → COLD) и миграция
  (as-is для `no_compress`).
- Revival из COLD: `max(score + N, 2.0)`, `no_compress = True`.
- Снятие `no_compress`: `score ≥ 8` И `changed_since_revival`.
- `user_fact` — амнистия 10 тиков от `forget_all`.

### ADR-014: Code Executor — ОТКЛОНЁН
Песочница для автономного исполнения кода. Отказ от реализации:
невозможна полная изоляция моими силами, дырявая песочница опаснее
её отсутствия. Не реализовано, не планируется.

### ADR-015: Retrieval hardening and admission gate
Шесть подзадач (все закрыты):

1. **Шаг 0** — инвариант «нагрев = показ» в `RecallMemoryTool._execute`.
   Порядок: сначала обрезка до limit, потом heat_facts.
2. **Шаг 1** — разделение `recall_memory` на три ступени:
   `_find_candidates` (retrieval) / `_rank_by_zone_score` (rerank) /
   `_gate_for_output` (gate).
3. **Задача №3** — LLM-ранжирование кандидатов. Модуль
   `memory/ranking.py`, `MAX_RECALL_RESULTS: 5 → 30`. LLM выбирает
   релевантные, только они греются.
4. **Шаг 2** — токенизация + Snowball-стемминг вместо substring.
   Модуль `memory/tokenizer.py`. «кот» больше не находит «который»,
   «коты» находит «кот».
5. **Шаг 3** — admission gate на секреты. Модуль
   `memory/admission.py`. Единственная точка в `_store_entry`.
   Контракт изменился: `None` → `dict {"stored", "reason", "key"}`.
6. **Шаг 4** — разделение счётчиков `_ticks_since_recall` /
   `_ticks_since_write`. `recall_memory(query, external=True/False)`.

**Осознанные отказы:** BM25, FTS5/SQLite, векторные эмбеддинги.
Корпус памяти ≤ 70 записей — O(N) мгновенен. Релевантность даёт LLM.

### ADR-016: JSON tool-call fallback
Ollama 0.35.1 не поддерживает tools для gemma3n (families определяет
capabilities). Решение: клиент сам определяет режим (native vs
fallback) и синтезирует `message.tool_calls` из текста.

- **Автодетект** через `/api/tags` → `capabilities` → кэш
  `self._tools_supported`.
- **Fallback** — `<tool_call>{...}</tool_call>` в ответе LLM,
  парсер синтезирует `tool_calls` формата Ollama.
- **P0-фикс** — нормализация истории в fallback: `role: "tool"` →
  `role: "user"`, `assistant.tool_calls` → текст `<tool_call>`.
  Иначе Ollama падает с 400 «Unable to generate parser».

**ReActLoop не меняется.** Клиент — единственное место, которое
знает, какая модель и какой режим.

### Фикс дедупа user_fact (2026-10-06, HANDOFF §7.1 + §7.3)

Живой баг: `remember_fact` использовал `recall_memory` для дедупа,
тот находил `dialogue_summary` по общим словам («зовут», «пользователь»),
LLM говорил «ДУБЛЬ» — и `user_fact` не создавался.

**Изменение публичного контракта `GradientMemory.recall_memory`:**
добавлен опциональный параметр `categories: list[str] | None`.
`None` = все каналы (обратная совместимость). Иначе — фильтр по
префиксу ключа до `':'`. Неизвестная категория → warning, не отказ.

**Двухслойный фикс:**
1. `RememberFactTool` вызывает recall с `categories=DEDUP_CATEGORIES`
   (`user_fact`, `task_state`). `dialogue_summary` в дедуп не попадает.
2. Вторая линия защиты: если в результатах дедупа по какой-то причине
   оказался чужой канал — запись не трогается, warning, создаётся новый
   `user_fact`. Это защита от будущих рассинхронов, не цель.

`RecallMemoryTool` (LLM-инструмент) НЕ менялся: он по-прежнему ищет
во всех каналах, ему нужен весь контекст.

**Новые константы в `memory/manager.py`:**
- `KNOWN_CATEGORIES` — для диагностики опечаток.
- `DEDUP_CATEGORIES` — источник правды для дедупа.

**Тесты:** `tests/test_recall_categories.py` (5),
`tests/test_user_fact_dedup.py` (3). 6 из 8 были красными до фикса,
2 — регресс-гарды.

## 4. Политика TDD (важно!)

**Принцип:** сначала красный тест, потом код. Не наоборот. Иначе
тесты пишутся «под реализацию» и не защищают от регрессий.

**Цикл:**
1. Пишем тест(ы) — должны **упасть** на текущем коде.
2. Смотрим, **почему** упали: если «метода нет» — хорошо,
   тест указывает на цель. Если «assert провалился» — тоже
   хорошо, тест фиксирует реальное поведение.
3. Пишем реализацию.
4. Запускаем — должны стать **зелёными**.
5. Если зелёные — коммит.

**Красный тест — не «падает случайно», а «падает осмысленно».**
Перед коммитом всегда проверяем: если откатить фикс, тест
покраснеет? Если нет — тест фиктивный, не защищает.

**Формат сообщений:**
- Все коммиты — на русском.
- Многострочные сообщения — через `commit_msg.txt` + `git commit -F`.
  PowerShell ломает `-m "..."` со спецсимволами.
- Один шаг = один коммит. Не смешивать несвязанные изменения.

**Формат диффов:**
- Полный файл, если изменения >50% или больше 3 мест.
- Дифф, если точечное изменение.
- Блочные комментарии `# блок: ... почему: ...` обязательны для
  новой логики.
- Всегда проверять: если что-то меняется в контракте публичного
  API — предупредить и предложить план миграции.

**Полный прогон перед коммитом:** `pytest -v`. Все 407 должны
быть зелёными.

## 6. Принятые решения (краткий чек-лист)

- **BM25 / FTS5 / vector** — не используем. Корпус мал, релевантность
  даёт LLM-ранк.
- **pymorphy3** — не используем. Snowball-стемминг достаточен.
- **Кросс-доменные редиректы SSRF** — не блокируем. Каждый хоп
  проверяется `preflight_check`; запрет ломает легитимные сценарии
  (bit.ly, канонизация домена) без выигрыша в безопасности.
- **Лимит fetch за сессию** — не делаем. `max_react_iterations=7`
  и так ограничивает цикл.
- **Family-aware SSRF-фильтр** — не делаем. aiohttp сам справляется
  через параметр `family`.
- **Code Executor (ADR-014)** — отклонён. Песочница без полной
  изоляции опаснее, чем её отсутствие.
- **`role: "tool"` в fallback** — нормализуем в `role: "user"`.
  Иначе Ollama падает с 400.
- **Admission gate только в `_store_entry`** — единая точка. Никто
  не обойдёт, включая фоновую компрессию.
  - **Категоризация каналов памяти** — по префиксу ключа до `':'`,
  без явного поля в entry. Причина: данные не мигрируют, контракт
  ключей уже де-факто сложился (`user_fact:`, `dialogue_summary:`,
  `task_state:`). Известные каналы — `KNOWN_CATEGORIES` в
  `memory/manager.py`.
- **`snowballstemmer` версия 3.1.1** — зафиксирована в `pyproject.toml`.
- **`.venv` портативный Ollama** — модель импортируется через
  `ollama create <name> -f Modelfile` (не `pull`, потому что GGUF
  локальный). Стор в `D:\OllamaModels\` (env `OLLAMA_MODELS`).

- Автоизвлечение задач при компрессии диалога.
- Вес приравнять к `user_fact` (score 40).

## 11. Что НЕ надо делать

- **Не пиши тесты после кода.** Только сначала красный, потом
  реализация.
- **Не переусложняй.** Если можно решить проще — решай проще.
  BM25, FTS5, vector — все отклонены по этой причине.
- **Не пиши код «на всякий случай».** Только то, что нужно сейчас.
- **Не меняй публичные контракты без предупреждения.** Если
  `_store_entry` возвращает `None` → `dict`, это изменение контракта,
  надо мигрировать всех вызывающих.
- **Не коммить, пока тесты красные.** Никогда.
- **Не используй PowerShell `-m "..."` для многострочных сообщений.**
  Через `commit_msg.txt` + `-F`.
- **Не пушь без `git log --oneline -3`.** Проверь, что коммит на месте.
