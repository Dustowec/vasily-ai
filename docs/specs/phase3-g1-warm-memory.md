# Фаза 3: G-1 + Warm-память

Дата: 2026-08-11
Статус: Draft
Ответственность: техлид + пользователь

## Цель

Подключить персистентность диалога к циклу агента без изменения внешнего CLI-поведения.

## Контекст

Сейчас `MemoryManager.remember()` и `MemoryManager.recall()` существуют, но не подключены к `AgentCore.handle_request()` и `ReActLoop.run()`.

Нужно закрыть gap G-1: агент должен запоминать диалог и использовать его при следующем запросе.

Warm-память в этом блоке понимается как короткоживущий диалоговый контекст, который живёт в hot-memory и очищается только периодической задачей планировщика.

## Утверждённые решения

1. Диалог сохраняется после обработки запроса, если ReAct вернул осмысленный ответ:
   - `status == "success"`;
   - или `status == "interrupted"`, если есть частичный ответ.
2. Перед запуском ReAct `AgentCore` читает диалоговый контекст из памяти и передаёт его в `ReActLoop`.
3. `ReActLoop` принимает optional-параметр `memory_context`.
4. `memory_context` не ломает Golden Prompts и не заменяет system prompt.
5. Очистка/сброс warm-памяти выполняется только через `PeriodicScheduler`.
6. Проверка и сброс warm-памяти внутри `ReActLoop.run()` запрещены.
7. Для первого этапа используем ключ:
   - `dialogue:last`

## Минимальные acceptance criteria

1. После первого запроса в памяти появляется `dialogue:last`.
2. Значение содержит:
   - текст пользователя;
   - ответ агента.
3. При втором запросе `ReActLoop` получает `memory_context`, содержащий данные предыдущего диалога.
4. Существующие тесты остаются зелёными.

## Открытые вопросы

Нет. Блок проектируется минимально, без усложнения.
