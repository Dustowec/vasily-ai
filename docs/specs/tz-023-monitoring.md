# ТЗ-023: Мониторинг и расширенные метрики

Дата: 2026-08-11
Статус: Draft
Фаза: 3

## Цель

Дать агенту внутренний сборщик метрик, чтобы команда status и логи показывали не только базовые счётчики, но и расширенное состояние ReAct-цикла.

## Минимальный scope

1. Создаётся отдельный модуль core/metrics.py.
2. Основной класс — MetricsCollector.
3. MetricsCollector должен считать:
   - общее число запросов;
   - успешные запросы;
   - ошибки;
   - прерванные запросы;
   - среднюю длительность запроса;
   - сумму итераций ReAct;
   - общее число вызовов инструментов;
   - число заблокированных одинаковых вызовов;
   - суммарное число использованных токенов.
4. Заблокированными считаются шаги, у которых result_preview начинается с:
   - [DUPLICATE CALL]
   - [LIMIT REACHED]
5. snapshot() возвращает обычный словарь для логов, CLI и тестов.

## Вне минимального scope

- HTTP/API endpoint.
- Prometheus / Grafana.
- Аутентификация.
- Персистентность метрик на диск.

## Acceptance criteria

1. Новый модуль core/metrics.py существует.
2. MetricsCollector.snapshot() возвращает детерминированный словарь.
3. record_request() обновляет счётчики запросов и длительность.
4. record_react_result() извлекает итерации, шаги инструментов и токены из ReActResult.
5. Существующие тесты остаются зелёными.
