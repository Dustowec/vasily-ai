# ТЗ-016.5: Санация логов и Crash Reporter

## Статус
Черновик. Создано 2026-08-09 по итогам ревью аналитической группы (разделы 2.4, 2.5).
Проектирование — сейчас. Реализация — перед Фазой 4 (облачный Crash Reporter).

## Цель
Защитить чувствительные данные (пользовательский ввод, промпты, запросы, URL,
содержимое страниц) в логах и crash-отчётах. Обязательное условие перед
включением облачной отправки отчётов (Фаза 4).

## ЧТО СЧИТАЕТСЯ ЧУВСТВИТЕЛЬНЫМ
Поля, содержащие пользовательский ввод или внешний контент:
- prompt, query, url, content, text, message, subject, tags

## ПОЛИТИКА САНАЦИИ

### Правило 1: Усечение
На уровнях INFO и WARNING чувствительные поля усекаются до
MAX_LOG_FIELD_LENGTH символов (по умолчанию 100) с добавлением "...".

### Правило 2: Метаданные на уровнях ошибок
На уровнях ERROR и CRITICAL вместо содержимого логируются только метаданные:
имя поля, длина, хеш (первые 8 символов sha256).

### Правило 3: Отладочное исключение
Если Config.sanitize_logs = False (локальная отладка) — поля логируются полностью.
Никогда не включать в production или при облачной отправке отчётов.

## РЕАЛИЗАЦИЯ

### logging_config.py
- Добавить sanitize_processor в цепочку shared_processors structlog
  (сразу после alert_level_processor).
- Процессор проходит по ключам event_dict и применяет правила 1-3.
- Список чувствительных ключей — константа SENSITIVE_FIELDS на уровне модуля.

### crash_reporter.py
- Добавить шаг санации перед сохранением отчёта: чувствительные поля
  в recent_logs усекаются по тем же правилам.
- Санация применяется ВСЕГДА, включая DEBUG-режим (отчёт может покинуть машину).

### config.py
- sanitize_logs: bool = True
- max_log_field_length: int = 100
- crash_report_lines: int = 50 (переносится из константы crash_reporter.py)

## КРИТЕРИИ ПРИЁМКИ
1. Запрос длиннее 100 символов в INFO-логе усечён.
2. ERROR-лог не содержит содержимого запроса — только длину и хеш.
3. При sanitize_logs=False логируется полный текст.
4. Crash-отчёт не содержит чувствительных полей длиннее 100 символов.
5. Существующие тесты проходят без изменений.

## СВЯЗИ
- ADR-004 (structlog) — процессор санации часть цепочки логирования.
- ТЗ-016 (ReAct) — логирование шагов R4 учитывает санацию.
- Фаза 4 — облачный Crash Reporter разрешён только при sanitize_logs=True.
