# ТЗ-016: ReAct-паттерн (Reasoning + Acting)

## Статус
Черновик. Создано 2026-08-09 по итогам ревью аналитической группы (раздел 2.6, ADR-005).

## Цель
Реализовать интеллектуальный цикл обработки запроса: LLM рассуждает, выбирает инструмент, получает результат и продолжает рассуждение до финального ответа.

## Архитектура
- Модуль: core/react_loop.py
- LLM-вызовы: OllamaClient (ADR-003)
- Инструменты: PluginRegistry (ADR-002)
- Межплагинная коммуникация: контекстный объект через AgentCore (ADR-002)
- Логирование: 4 журнала по ADR-004

## ОБЯЗАТЕЛЬНЫЕ ТРЕБОВАНИЯ (из ревью)

### R1. Обработка ошибок плагинов
- Вызов tool.execute() обёрнут в try/except.
- При исключении в историю LLM возвращается сообщение: {"role": "tool", "content": {"error": str(e)}}.
- Падение плагина НЕ прерывает цикл ReAct.
- Ошибка логируется в plugins.log и interaction.log на уровне ERROR (alert_level=CRITICAL_WARNING).

### R2. Лимит вызовов инструментов
- Счётчик вызовов каждого инструмента в рамках одной сессии.
- Лимит: 3 вызова на инструмент за сессию.
- При превышении — принудительное завершение цикла с сообщением о превышении лимита.
- Защита от зацикливания LLM.

### R3. Прерывание пользователем (Ctrl+C)
- Обработка KeyboardInterrupt внутри цикла ReAct.
- Корректный выход с возвратом текущего прогресса (частичного результата).
- Логирование прерывания в core.log на уровне WARNING (alert_level=WARNING).

### R4. Пошаговое логирование
- core.log — начало и конец итерации, итоговое число шагов.
- llm.log — отправленный запрос и полученный ответ LLM.
- interaction.log — вызов плагина и возвращённый результат.
- plugins.log — детали выполнения плагина.
- Каждый шаг несёт request_id для сквозного трейсинга.

## ДОПОЛНИТЕЛЬНЫЕ ТРЕБОВАНИЯ
- Максимум итераций ReAct на запрос: 10 (настраивается через Config).
- Санация: пользовательский ввод в логах усечён до 100 символов (связано с ТЗ на санацию логов).
- Каждый вызов инструмента проходит через централизованную политику обработки ошибок (ADR-002).

## КРИТЕРИИ ПРИЁМКИ
1. Агент обрабатывает сложный запрос с использованием двух и более инструментов.
2. Падение плагина не прерывает цикл; LLM получает ошибку и может выбрать другой путь.
3. Превышение лимита вызовов завершает цикл с понятным сообщением.
4. Ctrl+C корректно выходит из цикла с возвратом прогресса.
5. Один запрос трассируется через все 4 журнала по request_id.
