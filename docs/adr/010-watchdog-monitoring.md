# ADR-010: Watchdog — Мониторинг и автовосстановление

**Date:** 2026-08-23
**Status:** Accepted
**Author:** User (Architect) + Tech Lead (Implementation)

---

## Context

Агент Vasily AI работает в локальной среде с несколькими критическими компонентами:

1. **LLM (Ollama)** — может упасть или зависнуть в рантайме.
2. **Плагины** — могут потерять связь с внешними сервисами или сломаться.
3. **Память** — файлы могут быть повреждены (например, при сбое питания или ошибке записи).
4. **Диск** — может заполниться, что приведёт к невозможности записи логов и памяти.

Текущая система имеет:
- `HealthCheck` при старте (проверяет модули один раз).
- `CrashReporter` при фатальных ошибках.
- `PeriodicScheduler` для фоновых задач.

**Проблема:** Нет фонового мониторинга и автоматического восстановления в рантайме. Если LLM упадёт через час после старта, пользователь увидит только ошибку при следующем запросе.

---

## Decision

Внедрить **Watchdog** — фоновый модуль мониторинга и автовосстановления.

### Принцип работы

Watchdog запускается как отдельная asyncio-задача в `AgentCore.run()` и выполняет проверки с заданным интервалом (по умолчанию 30 секунд).

### Проверяемые компоненты

| Компонент | Проверка | Действие при сбое |
|-----------|----------|-------------------|
| **LLM (Ollama)** | `health_check()` через `/api/tags` | Пересоздать клиент → повторная проверка → 2 попытки → Crash-репорт + уведомление пользователя |
| **Плагины** | `echo.execute("ping")` | Перезагрузить PluginRegistry → повторная проверка → 2 попытки → логирование фатала |
| **Память** | Валидность JSON-файлов (try/except) | Восстановление из временной копии → при неудаче логирование ERROR |
| **Диск** | Свободное место < 500 МБ | Логирование WARNING |

### Алгоритм восстановления (для LLM и плагинов)

1. Фиксация сбоя → запись WARNING в лог.
2. Попытка перезапуска №1 → реинициализация модуля.
3. Ожидание 5 секунд (конфигурируется).
4. Повторная проверка.
5. Если успех → логирование INFO.
6. Если провал → попытка перезапуска №2.
7. Ожидание 5 секунд.
8. Финальная проверка.
9. Если успех → логирование WARNING (восстановлено со второй попытки).
10. Если провал → Crash-репорт + уведомление пользователя.
