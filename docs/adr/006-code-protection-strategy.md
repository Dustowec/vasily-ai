# ADR-006: Защита кода только после стабилизации

## Статус
Принято

## Контекст
Проект содержит интеллектуальную собственность:
- Уникальная база знаний тегов Danbooru
- Алгоритмы генерации промптов
- ReAct-логика агента
- Система памяти

**Риск:** Конкуренты могут декомпилировать код и скопировать логику.

**Инструменты защиты:**
- **PyArmor** — обфускация Python-кода
- **Nuitka** — компиляция Python в C, затем в бинарник
- **HWID lock** — привязка к железу пользователя

## Решение
Применять защиту кода **только после** завершения всех фаз разработки и стабилизации.

**Правило:** Code Freeze (защита кода) применяется только тогда, когда:
1. ✅ Все фичи реализованы
2. ✅ Все баги исправлены
3. ✅ Код покрыт тестами
4. ✅ Проведено нагрузочное тестирование
5. ✅ Нет активных изменений в логике

**Почему не раньше:**
1. **PyArmor ломает трейсбеки** — невозможно понять, где упал код
2. **Nuitka скрывает имена переменных** — отладка становится адом
3. **Защита усложняет работу с asyncio** — могут быть race conditions
4. **Каждое изменение требует перекомпиляции** — замедляет разработку

**Процесс защиты:**
\\\ash
# 1. Компиляция через Nuitka
nuitka --standalone --onefile vasily_ai/main.py

# 2. Обфускация через PyArmor
pyarmor obfuscate --output dist/protected main.py

# 3. Добавление HWID lock
pyarmor runtime --bind-device "hardware_id"
\\\

## Последствия

### Положительные:
- ✅ Код защищён от реверс-инжиниринга
- ✅ Можно продавать лицензии с привязкой к железу
- ✅ Бинарник не требует установленного Python

### Отрицательные:
- ❌ Невозможно отлаживать защищённый код
- ❌ Каждое изменение требует перекомпиляции
- ❌ Увеличивается размер дистрибутива
- ❌ Могут быть проблемы с asyncio и тредами

### План действий:
1. **Фазы 0-4:** Разработка без защиты (открытый код)
2. **Фаза 5:** Стабилизация, тестирование, code freeze
3. **Фаза 5.1:** Применение PyArmor + Nuitka
4. **Фаза 5.2:** Тестирование защищённой версии
5. **Фаза 5.3:** Релиз
