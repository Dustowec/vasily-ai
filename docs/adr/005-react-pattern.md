# ADR-005: ReAct паттерн для агента

## Статус
Принято

## Контекст
Агент должен решать сложные задачи, которые требуют:
1. Рассуждения (понимание задачи)
2. Действия (вызов инструментов)
3. Наблюдения (анализ результатов)
4. Итерации (повторение до решения)

**Пример сложной задачи:**
Пользователь: "Найди информацию о новом альбоме группы X и сгенерируй арт в стиле обложки"

**Простой подход (не работает):**
1. LLM пытается ответить сразу → галлюцинации
2. LLM не знает, какие инструменты доступны
3. Нет обратной связи от инструментов

## Решение
Использовать **ReAct (Reasoning + Acting)** паттерн.

**Алгоритм:**
\\\
1. LLM получает задачу + список доступных инструментов
2. LLM думает: "Мне нужно сначала найти информацию, потом сгенерировать арт"
3. LLM вызывает инструмент: web_search("группа X новый альбом")
4. Агент выполняет инструмент, возвращает результат LLM
5. LLM наблюдает результат, думает дальше
6. LLM вызывает инструмент: art_generator("стиль обложки альбома X")
7. Агент возвращает финальный ответ пользователю
\\\

**Техническая реализация:**
\\\python
async def react_loop(user_input: str, max_iterations: int = 5):
    history = [{"role": "user", "content": user_input}]

    for i in range(max_iterations):
        # 1. LLM думает
        response = await llm.chat(
            history,
            tools=plugin_registry.get_tools_schema()
        )

        # 2. Если LLM решила вызвать инструмент
        if response.has_tool_call():
            tool_name = response.tool_call.name
            tool_args = response.tool_call.arguments

            # 3. Выполняем инструмент
            tool = plugin_registry.get(tool_name)
            result = await tool.execute(**tool_args)

            # 4. Добавляем результат в историю
            history.append({"role": "tool", "content": result})
        else:
            # 5. LLM дала финальный ответ
            return response.content

    return "Превышено количество итераций"
\\\

## Последствия

### Положительные:
- ✅ Агент может решать сложные многошаговые задачи
- ✅ LLM сама решает, какие инструменты использовать
- ✅ Есть обратная связь от инструментов (меньше галлюцинаций)
- ✅ Можно добавлять новые инструменты без изменения логики агента
- ✅ Прозрачность: видно, как агент рассуждает

### Отрицательные:
- ❌ Больше вызовов LLM (дороже, если используется облачная модель)
- ❌ Сложнее отлаживать (много итераций)
- ❌ Риск бесконечного цикла (нужен max_iterations)
- ❌ Требует, чтобы LLM поддерживала function calling

### Альтернативы, которые рассматривали:
1. **Rule-based routing** — отклонено, потому что негибко
2. **Chain-of-Thought** — отклонено, потому что нет действий
3. **Plan-and-Execute** — рассматривается как дополнение к ReAct
